## Route and localization decisions

- Routes created: 58 (including dynamic route patterns).
- `/admin/login` and `/admin/mfa` are outside the protected console layout. Admin console pages call `getAuthorizationContext()` and require an active staff role; the helper requires aal2 MFA assurance for staff. Customer identities are redirected to `/` and unauthenticated visitors to `/admin/login`.
- Customer account child routes use `getAuthorizationContext()` and redirect anonymous visitors to `/auth/login`. Public storefront, account gateway and customer auth routes remain public.
- Fine-grained admin route checks use permission codes available in the Task 003 authorization context. Route visibility is not treated as authorization.
- `docs/TRD.md` §22 lists the locale route convention as an open decision; `docs/APP_FLOW.md` §2.4 says final locale prefixes and route naming may be standardized during implementation. This implementation preserves the documented unprefixed URLs and does not introduce `/en` or `/ne`. The locale utility continues to support `en` and `ne`, with `en` as default. The final locale URL convention remains unresolved.
- `docs/UI_UX_DESIGN.md` §4.1 records unresolved source typography and palette conflicts. This shell uses centralized Stitch YAML color values and retains the existing root font setup pending design approval.
